# 見出しごとの要点（syudan/_src/notes/）の作り方

県の資料が差し替わって `build.py` が「要点のない見出し」を出したとき、または翌年度の資料に切り替えたときに、この手順で作り直す。
2026-10-29 に全485見出しをこの手順で作った（台帳 P65 追記）。

## 決まり
- 県の資料の文は写さない。自分の言葉でまとめる（名称・条番号・数値・期日はそのまま）。県のサイトは「掲載されている情報は原則として福岡県に帰属」としている。
- 載せるのは、照合係2人がそれぞれ原文と照らして**2人とも合格**とした文だけ。
- 原文の抜き出し（根拠）は照合にだけ使い、リポジトリには入れない。作業はリポジトリの外のフォルダで行う。

## 手順（作業用のフォルダ W を、リポジトリの外に作る。このフォルダのファイルを W にコピーして使う）
1. `python3 syudan/_src/extract.py W/work`（資料を取って見出しと索引を作る）
2. `python3 W/sections.py W/work W/sections`（見出しごとの本文に切る。sections.py の中の REPO を確かめる）
3. 本文を4万字ほどずつのかたまり（chunks/<名前>.json: {"chunk","doc","items":[sections の項目],"chapters":{}}）に分け、
   かたまりごとに下書き係（Agent）へ `RULES_draft.md` を渡して drafts/<名前>.json を作らせる（並行でよい）
4. `python3 W/check_drafts.py`（根拠の抜き出しが原文にあるか・数字・写しすぎ・使わない言葉を機械で確かめる。groups.json に {名前: [かたまり]} を書く）
5. かたまりごとに照合係を2人（A・B、互いの結果を見せない）立て、`RULES_verify.md` で verify/<名前>-A・-B.json を作らせる
6. 2人とも合格の文を集め、不合格の文は照合係の直し（fix）で置き換えて `prep_fix.py` で round2/ を作り、
   別の照合係2人に `RULES_verify2.md` で確かめさせる。2人とも合格なら直した文を載せる
7. 合格した文を見出しの文字ごとに `syudan/_src/notes/<資料>.json`（[{t, gist, points, shiteki}]）へ書き、`python3 syudan/_src/build.py`
   （集計は merge.py。2026-10 の作業では途中で見出しが増えたため、鍵を付け替える版（v4）になっている。作り直すときは drafts_v4・verify_v4 を drafts・verify と読み替える）
